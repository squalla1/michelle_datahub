## P0

**1 · calendar 无未来事件**
产品需求:日历/晨报类页面要回答「今天和接下来三周有什么」——需要 **回溯 7 天 + 前瞻 ≥3 周** 的事件窗,财报事件至少要有下一期排期。
查:`module=calendar` 任意拉取,统计 `event_date > 今天` 的条数。
现状:**0 条**(全库 event_date 区间 1998 → 今天,6 次独立复测;我方过滤闸 quarantined=0,不是被我们滤掉的)。疑似拉取窗口只落历史(FMP from/to 未含前瞻窗)。

**2 · 三个模块的历史保留(约 5 天内要回复)**
- **calendar** — 产品需求:能**完整拉到库内全量**(或给区间参数,见 #16)。现状:库在快速回填,全量四天 `5,206 → 7,206 → 8,253 → 10,157`(日增 ≈1,900);我方拉取上限 20,000 条,按此速度 **≈5 天后到顶**,到顶那轮日历就是不全的。要:回填的目标量级/有无上限;若会持续增长,请给区间参数或告知上限,我方好定拉取策略。
- **market** — 产品需求:行情页要显示 **30 天涨跌(需历史 ≥35 天)**;后续要 YTD/1Y(需 **≥13 个月**)。现状:全库最老一行 **2026-07-29**,只有约 9 天(≈12,417 行),30D/YTD/1Y 无法计算。要:确认是否有 retention 在裁;先保 ≥35 天,≥13 个月可分期。
- **company** — 产品需求:公司资料页需要内容可回溯、条目不无声消失。现状:数小时内两次全量 `1,418 → 1,347`,掉 71 条(滚动窗口)。要:告知窗口大小与滚动规则,我方按此设计缓存。

**3 · macro `CPIAUCSL` 完全没数**
产品需求:宏观 13 指标全集可用,最新期滞后 ≤75 天(CPI 是引用最频的指标之一)。
