## 一、已修复项详情(附验证数据)

### 1. Google News 正文与溯源(P1-1、P1-2)

经核验,问题比反馈描述更严重:Google News 链接此前累计尝试抽取 **18,304 条,
成功 0 条**。根因与你们的判断一致 —— 该类链接是加密跳转,直接抽取必然失败。

本次修复后,系统会先解析出**真实原文地址**再抽取正文,并把原文地址放入
`payload.canonical_url` 字段,供引擎做去重与溯源。

**验证结果**:抽样 200 条此前失败的 GN 链接 —— 原文地址解析成功 **200/200**,
正文抽取成功 **97 条(48.5%)**;未成功的部分是原文站点自身的付费墙/反爬所致,
属于该来源的客观上限。历史积压的 1.8 万条已重新排队,将随后台任务在数日内
逐步补齐,补齐进度不需要你们做任何操作。

### 2. payload 源侧字段(P1-3)

核验属实:market/macro/calendar 的 payload 此前 100% 为空,news 为 72%。

已按反馈中的分工原则修复:**凡能从数据源注册信息直接得到的字段,由 API 侧在
入库时自动填充**,包括 `topic / region / platform / medium / asset_class /
instrument / indicator / event_type / calendar_type / data_type / person` 等;
抓取环节能拿到更准确值时以抓取值优先。**存量 75,170 条已全部补填完成**(即时
生效)。`symbol / exchange` 等数值型字段依赖结构化数据源,归入 ④ 一并解决;
实体/ticker/情绪等 NLP 派生字段按约定仍由引擎侧负责。

### 3. published_at(P1-4)

核验属实:calendar 98%、company 84%、macro 72% 为空,根因是这些源属于"页面
链接抽取"类型,本身不携带时间。修复后,正文抽取时会顺带解析原文页的发布时间
并回填。**边界说明**:日历/列表类页面本身无发布时间概念,该部分无法凭空补齐,
彻底解决依赖 ④ 的结构化源接入;过渡期建议按入库时间(`by=fetched`)做排序与
增量同步。

## 二、非缺陷事项的说明与正确用法

### ① macro / calendar "返回空"

**数据在库**(macro 132 条、calendar 1,090 条,其中当日入库 438 条),显示为空
是查询口径所致:按类型接口默认返回"**当天 + 按发布时间**"的数据,而 calendar
条目 98% 无发布时间、macro 并非每日更新,默认口径下自然为空。

**请调整为**:`?by=fetched`(按入库时间)或显式指定 `?date=`。该口径说明已补入
API 文档。macro 的源覆盖目前确实偏少(3 个源在产数),扩充随 ④ 推进。

### ② events / opinion 中的 Hacker News

这不是接口错配:数据源注册表的「全球事件」页本身登记了 GitHub/Show HN 技术
事件源(该模块条目量最大的一个源),「关键舆论平台」页登记了 HN 的多个板块。
API 按注册表忠实交付。同时说明:**GDELT 地缘事件在库约 390 条,Reddit
r/popular 在库 304 条**(并非只有 HN)。

**两个选项供选择**:引擎侧按 `source_id` 过滤(源清单可经
`GET /api/v1/sources?module=events` 查询);或由你们修订注册表归类,系统自动
跟随。微博热搜/StockTwits 确实未接通(对方反爬),归入 ④ 排期。

### ③ person 返回空

该模块 286 个源中 256 个来自 twitterapi.io(计费 $0.15/千条,按量无月费),
接口联通性已验证正常,**开通付费后数据即自动流入,无需任何开发**。
是否开通请业务侧决策,确认后我们当天配置生效。

### ④ 结构化行情/财务(最大缺口,待排期)

确认属实并认同其第一优先级:当前 market/company 的内容确为新闻文本,
S-PRICE/S-FIN 等结构化数值尚未覆盖。这属于**新数据源接入**而非缺陷修复,
涉及两类:免费官方 API(世界银行/各国央行/统计局等,42 个源已验证联通)与
付费源(FMP,覆盖 29 个源,约 $99/月)。

**对反馈问题 3 的正式答复**:建议**并入现有 `content` 接口的 `payload`**
交付 —— 字段标准已预留 `symbol / instrument / indicator / period` 等,引擎
无需对接新端点;若后续需要高频行情时间序列,再增设专用端点。请确认形态与
优先顺序(免费官方 API 先行,或 FMP 一步到位),我们据此排期。
