## 一、已修复的 bug(附验证数据)

### 1. Google News 正文抽取失败(P1-1)+ canonical URL(P1-2)

**核实**:比反馈描述更严重 —— GN 链接曾尝试抽取 **18,304 条,成功 0 条(0%)**;
非 GN 源成功率 90%。根因确认:`news.google.com/rss/articles/CBMi…` 是 base64
编码跳转,任何抽取器都拿不到原文。

**修复**(`datahub/ingest/enrich.py`):富化时先解码出真实原文 URL,再抽取正文;
解码得到的 canonical 链接写入 `payload.canonical_url`(供引擎去重/溯源);解码
失败视为瞬时问题保留重试(不再永久标失败)。

**验证**:实测 200 条 GN 链接 —— **解码成功 200/200**,正文抽取 **97/200(48.5%,
原 0%)**;未抽出的是解码后原文站自身的付费墙/反爬,属天花板。已把存量 **18,429
条**失败标记重置为待处理,富化任务将按新逻辑自动重做。

### 2. payload 源侧字段回填(P1-3)

**核实**:属实 —— market/macro/calendar 的 payload 100% 为空,news 72% 全空。

**修复**(`datahub/ingest/runner.py`):入库时从注册表行自动回填源侧字段
(fetcher 提供的值优先):

| 模块 | 回填字段(来源) |
|---|---|
| news | `topic`(二级分类);区域类源另填 `region` |
| opinion / channel | `platform`/`medium`(一级分类)、`topic`(二级分类) |
| person | `person`(渠道名)、`platform`(按 URL 域名识别 X/微博/雪球…) |
| market | `asset_class`(一级)、`instrument`(二级) |
| macro / events / calendar / company | `indicator` / `event_type` / `calendar_type` / `data_type`(二级分类) |

**存量**:已对生产库 **75,170 行**完成一次性回填(现有键不覆盖)。
`symbol/exchange` 等数值字段依赖结构化源(见 ④);NLP 派生字段按分工留引擎。

### 3. published_at 缺失(P1-4,部分)

**核实**:属实 —— calendar 98% / company 84% / macro 72% 为空(爬虫类源只有链接
没有时间)。

**修复**:富化抽正文时顺带解析文章页的发布时间元数据,回填缺失的
`published_at`。**边界**:日历/列表页类内容本身无日期,无法凭空补 —— 彻底解决
依赖结构化源接入(见 ④)。过渡期请用 `by=fetched` 排序/增量。

## 二、非 bug 事项的说明

### ① macro / calendar "返回空"(P0)

**不是没接线,是默认查询口径 + 数据特性**。实测库存:macro 132 条、calendar
1,090 条(当天入库 438 条)。但按类型接口默认取"**当天 + 按发布时间**",而:
calendar 条目 98% 无发布时间、macro 非每日更新 → 默认查询看起来是空的。

**正确用法**:`GET /api/v1/content/calendar?by=fetched`(按入库时间)或显式
`?date=`。此口径说明已补入 API 文档"使用注意"。macro 覆盖确实偏少(3 个源在
产数),扩充依赖 ④。

### ② events / opinion 出现 Hacker News(P1-5 / P0)

**不是 API 路由 bug**。注册表 `2_全球事件` 页本身登记了 "GitHub Trending +
Show HN" 源(500 条,该模块单源最大),`7_关键舆论平台` 页登记了 HN 前页/Show
HN/Ask HN —— API 忠实按注册表交付。GDELT 地缘事件同时在库(约 390 条),
**Reddit r/popular 也在**(304 条,反馈漏看)。

**引擎侧对接**:用 `source_id` 区分(`GET /api/v1/sources?module=events` 可查
源清单);若认为 HN 不该在这两个模块,请修订注册表归类,系统会跟随。
微博热搜/StockTwits 确实未通(反爬/桥接失效),归入 ④ 排期。

### ③ person 返回空(P0)

数据源本身需付费:286 个源中 256 个是 twitterapi.io($0.15/千条,按量),
**已验证接口联通**,开通付费即有数据,零开发。是否开通请业务侧决策。

### ④ 结构化行情/财务(P0 第一行,最大缺口)

**属实且认同优先级**。当前 market/company 内容确为新闻文本,S-PRICE/S-FIN 等
结构化数值未覆盖。这不是"修 bug"而是新数据源接入,涉及:免费官方 API
(世行/央行/统计局等 42 个源已验证联通)与付费源(FMP 29 个源,≈$99/月)。

**形态答复(反馈问题 3)**:建议**并入现有 `content` 的 `payload`** ——
schema 已预留 `symbol/instrument/indicator/period` 等字段,引擎无需对接新端点;
若后续要高频行情时间序列,再单开专用端点。请确认后我们排期接入顺序。

## 三、部署与验收

```bash
# 服务器生效(新增依赖 googlenewsdecoder,必须 rebuild)
cd /opt/datahub/app && git pull
cd deploy && docker compose build api scheduler && docker compose up -d api scheduler

# 验收
curl "https://mai.polarisagi.com/api/v1/content/news?limit=3&by=fetched"
#   → payload 应含 topic(回填)及 canonical_url(GN 条目)
```

`DATAHUB_FULLTEXT_BATCH_SIZE`/`INTERVAL_MINUTES` 加速)。
