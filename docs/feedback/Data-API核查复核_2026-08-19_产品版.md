## 一、本次上线的新能力

### 1.1 日历可以按事件日期查区间(新增)

此前日历接口只能取"当天",做不了"本周财报""下个月的经济数据发布"这类视图。现在两个内容接口都支持 `event_from` / `event_to`,按事件日期升序返回。

```bash
curl "https://mai.polarisagi.com/api/v1/content/calendar?event_from=2026-08-25&event_to=2026-09-05&limit=200"
```

```json
[{"title": "9633.HK 财报 2026-08-25",
  "payload": {"symbol": "9633.HK", "event_date": "2026-08-25",
              "epsEstimated": 0.923, "revenueEstimated": 33931260000,
              "calendar_type": "财报", "calendar_region": "美股"}}]
```

传了区间即不套用"当天"默认值。日历页的周视图、月视图、"接下来七天"模块都可以直接接。

### 1.2 日历有未来事件了

此前日历只有当天及过去的条目,前瞻部分为空。现在每次刷新都会取 **未来 28 天** 的事件,当前覆盖 08-20 至 09-16,**逐日无空缺**。财报、分红、拆股、IPO、经济数据发布均在内。

### 1.3 经济数据发布带时区标注

经济日历条目的 `event_date` 统一为 **UTC**,并以 `event_timezone` 字段显式标明。前端换算到用户本地时区时不必再猜基准。

```json
{"title": "[JP] Foreign Bond Investment (Sep/12)",
 "payload": {"event_date": "2026-09-16 23:50:00", "event_timezone": "UTC",
             "country": "JP", "currency": "JPY", "impact": "Low"}}
```

### 1.4 行情条目有了规范的资产类别

`asset_class` 此前混着中英文和"二级市场"这类市场分层值,无法用来分组。现在收敛为六个固定值:**股票 / 指数 / 外汇 / 商品 / 加密货币 / 债券**。行情页按资产类别分 Tab、做筛选器都可以直接用这个字段。

### 1.5 主要货币对与基准品种必定出现

此前行情按成交量取每类前 100,EURUSD 在清淡日会掉出榜单,USDJPY 因数据源报成交量为 0 从未进过库。现在基准品种每轮必采,其余名额再按成交量填充;基准条目带 `benchmark: true`,可用于置顶或固定展示。

```json
{"title": "^TNX 4.661 (-0.0450003)",
 "payload": {"symbol": "^TNX", "price": 4.661, "change": -0.0450003,
             "benchmark": true, "asset_class": "指数"}}
```

### 1.6 宏观指标带单位和更新频率

数值此前是裸数字,前端无法判断"4.66"是百分比还是指数点。现在每条带 `unit` 与 `frequency`,可直接拼接显示;每个指标的历史观测由 24 期提升到 36 期。

```json
{"title": "M2SL = 20792.2 十亿美元 (2023-07-01)",
 "payload": {"indicator": "M2SL", "value": 20792.2, "unit": "十亿美元",
             "frequency": "月", "period": "2023-07-01"}}
```

单位对照:利率与失业率为 `%`,期限利差为 `百分点`,CPI 类为 `指数 (1982-84=100)`,PCE 与工业产出为 `指数 (2017=100)`,非农为 `千人`,M2 为 `十亿美元`,GDP 为 `十亿美元 (2017年不变价, 年化)`,贸易差额为 `百万美元`,成屋销售为 `千套 (年化)`。

### 1.7 申报数据带公司名

此前 SEC 申报条目的标题是注册号(如 `333-297525`),页面上无法展示。现在带公司名、表格类型、CIK 和真实申报文件链接。

```json
{"title": "MOBIX LABS, INC 424B3",
 "url": "https://www.sec.gov/Archives/edgar/data/1855467/...",
 "payload": {"companyName": "MOBIX LABS, INC", "form_type": "424B3",
             "cik": "0001855467", "event_date": "2026-08-19 00:23:24"}}
```

## 二、数据质量修正(前端无需改动,但内容会变干净)

| 项 | 此前 | 现在 |
|---|---|---|
| 日历混入网站导航 | 央行日历里出现 `Speeches`、`Our people`、`Back to Home` 等栏目名 | 日历条目必须带事件日期才入库,导航链接不再进入 |
| 日历混入服务器默认页 | 出现 `nginx.org`、`nginx.com` 两条 | 识别为抓取失败,不再入库 |
| 公司页混入无关链接 | 出现 `Best Mortgage Lenders`、`沪ICP备…号`、`Français` 等 | 只保留正文链接,财报电话会纪要等真实内容正常产出 |
| 新闻出现"未来发布时间" | 个别来源的条目时间戳晚于抓取时间,按发布时间排序时会置顶 | 小幅偏差按来源时钟误差处理并校正,大幅偏差的时间戳置空 |
| 日历事件种类字段不可用 | 35 个日历源写入的是市场/地区(`全球`、`美国`) | `calendar_type` 收敛为 13 个事件种类,市场/地区移入 `calendar_region` |

`calendar_type` 的固定取值:财报 / 分红 / 拆股 / IPO / 公司行动 / 公司IR / 监管备案 / 经济 / 央行 / 国债拍卖 / 能源商品 / 加密事件 / 科技活动。

## 三、未来几天的预期变化

系统保留最近 7 天的内容。上线前入库的历史脏条目不作删除,会在 **08-22 至 08-26 之间** 随保留窗口自然消失,包括央行日历中的 521 条栏目链接、SEC 申报中的 687 条注册号条目、以及两条服务器默认页。

这段时间内前端如果看到上述条目,属于预期内的过渡状态,**不需要报障**。08-26 之后仍存在则请反馈。

另有两个数据源(巨潮资讯-公司资料、FMP 业绩说明会日期)因与其他源内容重复已停用,其历史条目同样在此期间过期。在此之前,消费侧仍需按重复条目容错。

## 四、仍然取不到的数据

以下几项经核实为**数据源接口无法实现**,不是抓取逻辑的问题,需要另行立项或换源。当前这些源不再产出脏数据,而是如实返回"未取到"。

| 数据 | 涉及来源 | 原因 |
|---|---|---|
| 央行议息日程 | 美联储、欧央行、日本央行、英格兰银行、中国人民银行 | 五家官网均未提供日历接口或日程订阅,页面上的"日期"是页面自身的更新时间而非会议时间,通用抓取无法判别哪些元素构成一个事件。需逐家开发专用解析或改抓官方日程页面 |
| 中债招标日历 | ChinaBond | 该站按访问来源的网络地址限制访问,服务器地址只能取到默认页面。需要配置境内出口或更换数据源 |
| 上交所互动问答 | 上交所 e 互动 | 页面内容由浏览器端动态加载,服务端返回的页面只有框架,且未提供公开接口 |
| 港交所披露信息 | HKEX News | 同上,为搜索型应用 |
| 股吧讨论 | 东方财富股吧 | 同上,帖子内容由浏览器端渲染 |
| 个股估值数据 | StockAnalysis.com | 该站登记用途为估值/市场数据,页面实际只提供站外新闻链接,通用抓取取不到估值数值。需接入专门的估值数据接口 |

## 五、需要产品确认的事项

### 5.1 数据更新频率

当前**所有数据源统一为每 4 小时更新一次**,来源登记表中"实时""10-15 分钟"等频率设置在生产环境未实际生效(原因已定位,修复方式明确)。

这意味着新闻类内容当前的最快可见延迟约为 4 小时。放开频率设置后,标记为"实时"的来源将改为 2 分钟一次,但 1,200 余个数据源同时提速会显著增加服务器负载,该主机在内容处理任务运行期间已出现接口响应变慢的情况。

请产品侧从数据新鲜度需求出发确认方向,三个选项:

1. **维持现状** —— 全部每 4 小时更新一次,负载最低;
2. **仅放开重点来源** —— 按优先级 P1 的来源恢复其声明频率,其余维持 4 小时;
3. **全部放开并扩容** —— 恢复全部频率设置,同时调整服务器规格。

建议选项 2,兼顾重点栏目的新鲜度与稳定性。确认后即可实施。

### 5.2 SEC 申报数据的定位

该数据源在来源登记表中登记为「锁定期解禁 (lock-up)」,但实际抓取到的内容是 S-1、424B 等**发行申报文件**,两者不是同一类信息。下游若按"锁定期解禁"的语义消费会产生偏差。

请确认处理方向:调整登记名称与分类以匹配实际内容,或更换为真正提供锁定期解禁日程的数据源。本次未作变更。

### 5.3 新闻配图的上限

新闻配图当前覆盖约 68%。未覆盖的部分主要是经聚合平台转发的财经内容,其落地页多为付费墙或有反爬限制的站点,系统会尝试补图但存在无法绕过的比例。建议前端为这部分内容准备兜底图。

## 六、接口速查

```bash
BASE=https://mai.polarisagi.com/api/v1

# 日历:按事件日期区间查询(新增)
curl "$BASE/content/calendar?event_from=2026-08-25&event_to=2026-09-05&limit=200"

# 财报日历 / 分红拆股 / IPO / 经济数据
curl "$BASE/content?source_id=408&limit=5"    # 财报
curl "$BASE/content?source_id=412&limit=5"    # 分红、拆股
curl "$BASE/content?source_id=414&limit=5"    # IPO
curl "$BASE/content?source_id=429&limit=5"    # 经济数据发布

# 行情:按资产类别筛选可用 payload.asset_class
curl "$BASE/content/market?by=fetched&limit=20"

# 宏观指标(带单位与频率)
curl "$BASE/content?source_id=543&limit=5"

# 各模块整体情况
curl "$BASE/stats"
```

完整接口文档见 `docs/API_REFERENCE.zh-CN.md`,或线上 `https://mai.polarisagi.com/docs`。

## 七、小结

08-17 提出的 14 项问题全部核实完毕,其中 11 项完全成立、2 项部分成立、1 项现象准确但成因需更正。多数问题的根源是修复代码未部署到线上,本次已完成部署并逐项验证。

前端可立即使用的新增能力有三项:日历区间查询、日历前瞻事件、行情资产类别分组。其余为数据质量修正,不需要改动即可看到效果。
